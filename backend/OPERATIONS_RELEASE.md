# Care operations release

This extends the existing shared backend, dashboards, Elite Care and Elite Work.

## Available workflows

- Incident reports for assigned shifts, employer investigation/resolution, immutable review entries, tenant isolation and email alerts without incident narratives.
- Per-shift location boundaries, configured by the owning employer before attendance starts. Server checks position, accuracy and freshness. Clock-out remains available. GPS alone does not prevent spoofing.
- Approved actual-hours CSV exports scoped to the employer, with export audit records and spreadsheet formula escaping. Selection uses the clock-in date in UTC; overnight hours are included in that row. Payroll providers must determine overtime, taxes, deductions and pay-period allocation. Repeated exports contain the same IDs and must not be imported twice.
- SMS phone verification, explicit consent, STOP suppression, signed status callbacks, delivery history and duplicate-event prevention. Provider timeouts are treated as uncertain sends and are not automatically retried.
- Web controls at /operations.html; mobile controls under Account / Care operations (employer) and Profile / Incident reports & SMS alerts (caregiver).

## External activation still required

SMS stays off unless SMS_ENABLED=true, TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_PHONE_NUMBER and SMS_WEBHOOK_BASE_URL are configured. Use the public API origin for SMS_WEBHOOK_BASE_URL, with no path. Configure the Twilio number's inbound webhook to POST /api/sms/inbound at that origin and complete the sender registration required for that number. Outbound status callbacks target /api/sms/status. Verify real inbound STOP and delivery before enabling public enrollment. Never put provider credentials in mobile builds or the web source.

Gusto, ADP and QuickBooks direct sync is **not implemented or connected** in this release. The integration catalog honestly shows provider setup requirements. Each needs an authorized production provider application and organization consent, then provider-specific employee mapping, reconciliation and sandbox validation before any sync can be enabled. Generic CSV export must not be represented as a certified vendor import.

SMS invitations are not sent automatically to unverified third-party numbers. Existing secure invitation links can still be shared through the device's messaging app.

## Verification

Disposable PostgreSQL tests cover tenant isolation, incident review history, geofence rejection and accepted attendance, approved-only payroll exports, invalid periods, CSV formula escaping, phone verification, consent, signed provider callbacks, STOP suppression, duplicate sends, and account deletion. Web DOM tests exercise safe rendering and actual form submissions. No real payroll, text messages, or incident alerts are generated by these tests.

Native devices and live providers need end-to-end validation after installation and activation. No claim of live SMS delivery or provider payroll synchronization is made.
